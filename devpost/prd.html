END-TO-END PRODUCT JOURNEY & STATE MACHINE
Split-View Workspace Architecture

Designed to eliminate context-switching. The developer always sees their active approved scope baseline right next to incoming requests.

LEFT: SCOPE ANCHOR v1.0 ACTIVE
Item #1: User Authentication
Email & password login flow
Item #2: Stripe Checkout
Standard credit card payment page
Item #3: Customer Dashboard
Order history and invoice downloads
RIGHT: REQUEST EVALUATION Input & History
"Can we also send SMS receipts via Twilio when someone buys?"
POSSIBLE_CHANGE Rule: Unmatched 3rd Party Vendor
Matched: #2 Stripe Checkout New: SMS / Twilio Integration

Rationale: Matches payment flow, but introduces new third-party SMS telephony service not present in Baseline v1.0.

Comparison Result Card Specification
  • Exact Status Badges: Strictly one of IN_SCOPE (emerald), POSSIBLE_CHANGE (rose), or NEEDS_REVIEW (amber).
  • Matched Baseline Tags: Displays which baseline item IDs were matched, with clickable anchors to view the item in the left panel.
  • Plain-Language Rationale: Cites concrete evidence—what overlapped and what novel requirements appeared.
  • Uncertainty Note: When evidence is ambiguous, explicitly states that human discretion is required rather than faking certainty.
  • Action Logging: Clicking Accept, Reject, or Clarify records the decision with an optional note, timestamp, and active baseline version. Clears input on success.
Baseline Immutability & Audit Integrity
  • Zero Silent Mutation: Once a baseline is approved (e.g. v1.0), it is permanently locked.
  • Draft Mode: Editing scope creates an unapproved draft. Incoming requests continue comparing against v1.0 until the draft is explicitly approved.
  • Sequential Versioning: Approving changes commits v2.0 with its own timestamp and items list.
  • Audit Preservation: Past decisions remain permanently linked to the baseline version active at that moment in history.
Resilience & Data Safety
  • Empty/Whitespace Brief: Validation error message; prevents empty baseline creation.
  • Unstructured Brief Fallback: Automatically converts raw text into a single editable card with an "Add Item" button for manual splitting.
  • No Network Transmission: 100% of data stays in browser local storage. No tracking, zero API keys.
  • Corrupted Storage Defense: Safely detects corrupted local storage schemas on boot and offers non-destructive recovery.
  • Export & Reset: Obvious "Export JSON" backup button and "Reset Project" modal with required confirmation.
Proof of Concept Acceptance Checklist
  • Project creation with custom workspace name
  • Brief paste with deterministic list parsing and single-card fallback
  • Explicit timestamped baseline approval as v1.0
  • Comparison engine assigning IN_SCOPE, POSSIBLE_CHANGE, or NEEDS_REVIEW
  • Result card with status, matched item pills, rationale, and uncertainty disclosure
  • Decision recording (Accept / Reject / Clarify) appended to History feed
  • Baseline version bump (v1.0 -> v2.0) with historical decision retention
  • Complete state persistence across browser refresh
  • JSON export and confirmed project wipe
  • Linear/Raycast dark theme with full keyboard accessibility
