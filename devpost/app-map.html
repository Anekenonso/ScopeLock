A permanent developer guide mapping how ScopeLock turns requests into deterministic evaluations and immutable audit records.

Three Core Code Locations
1
src/components/RequestInput.tsx

The Ingestion Surface: Captures incoming client messages, provides one-click sample pills for fast testing, and handles Ctrl+Enter submission.

2
src/lib/comparator/deterministic.ts

The Classification Engine: Pure, decoupled implementation of ScopeComparator. Normalizes text, matches concept synonyms, detects third-party vendors or novel capabilities, and returns status, matched item IDs, and plain-language rationale.

3
src/lib/storage/repository.ts

The Audit Repository: Manages defensive read/write operations against browser localStorage with Zod runtime schema validation, ensuring historical decisions stay permanently tied to their active baseline version.

To Change This, Start Here
  • Add new novel vendors or capability rules: Edit src/lib/comparator/rules.ts under NOVEL_CAPABILITY_RULES.
  • Tune classification score thresholds: Edit src/lib/comparator/deterministic.ts in evaluate().
  • Modify baseline or decision data schemas: Edit src/lib/storage/schema.ts.
A Practice to Reuse: Contract-Driven Kill-Tests

Before touching the UI, we defined 12 synthetic test cases in killTestCases.ts. When automated tests ran in Slice 1, they immediately caught subtle keyword gaps (like hyphenated token splitting and payment concept synonyms).

The Takeaway: Directing an agent works best when you establish an executable verification contract (a test suite) first. It provides objective ground truth that catches hallucinations or logic omissions before they reach the interface.
